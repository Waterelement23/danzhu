# 手机全场拖动实施计划

用户已批准：取消独立发射区，场地内拖动，边缘悬浮控件，首次引导、误触保护和取景/负载复查。在当前独立 worktree 顺序实施，不另建任务。

**目标：** 手机横竖屏都把原操作面板占用的面积还给场地，同时可从空白处瞄准。
**架构：** 保留单个 WebGL 画布、现有相机与物理；仅移动 DOM 控件并扩展画布触摸手势。共享 `touchAim` 负责方向/力度，手机取景预留向后拖动距离。桌面仍需按住自己的球。

- [x] `match-ui.ts` 增加按视口限制的满力度拖动距离；`turn-camera.ts` 接收垂直安全取景范围。在测试里用真实 Three.js 投影验证横竖屏两球取景和拖动空间，保留 5px 点击死区。
- [x] `scene.ts` 删除独立触控区绑定。触摸可从整个画布开始，鼠标保留球附近命中范围。多指、pointercancel、失去捕获、窗口切换均取消，按住时锁镜头。方向继续基于相机 yaw。
- [x] `main.ts` 移除 aim-pad，改为 scene 内的非阻挡悬浮层：顶部倒计时/全景/菜单，底部按需发球/准备/邀请；力度提示及取消仅手势中出现。声音、帮助、离开进入菜单；首次成功发射后持久隐藏引导，帮助可重新显示。
- [x] `style.css` 删除 242px 底栏和 190px 横屏栏，画布占满原空间；悬浮层仅控件接收点击，考虑刘海及 Home 安全边距。不增加模糊或渲染通道。
- [x] 运行 `npm test`、`npm run build`。手机横竖屏浏览器验证面积、首次引导、空白处拖动、轻点/回原点/双指/系统取消、按钮隔离、两次发球及回合交接；复查手机像素上限及帧率。桌面球附近拖动回归。
- [ ] 提交推送、部署并进行公网资源、房间和手机交互检查；记录结果与回滚镜像。真机温度和微信/Safari 手感不以模拟测试代替。

## 本地验证

- 101 项单元/联机测试通过；生产构建通过。
- CDP 原生触摸事件验证轻点不发射、空白处蓄力、拖回原点、第二根手指、系统取消、菜单隔离、首次引导收起、两次入场和自动镜头。`scripts/mobile-direct-aim-check.js` 可通过 Playwright MCP 在开发服务上复现。
- 手机竖屏 390×844：画布布局从 390×528 增至 390×770，内部像素 487×962。横屏 844×390：画布布局 844×316，内部像素 1055×395。保持活动 30fps / 静止 15fps、DPR 上限 1.25、90 万像素上限；画面扩大后的实际像素数也增加，不据此声称功耗不变。
- 两个独立联网页面验证自动镜头、相机朝向下的触摸拖动、转场中出手锁定、下一回合交接。桌面验证空白处不触发、球附近拖动和 Esc 取消。页面无 JavaScript 错误。
- 横屏发球控件移到左下侧，避免覆盖发球弹珠；取景仅对下方预留拖动距离，避免上下对称留空导致画面过度缩小。
