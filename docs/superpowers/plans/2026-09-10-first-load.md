# 首次加载优化

用户授权优化冷启动，并新增遮罩与进度条，避免展示不完整场景。

证据：公网 GLB 9,900,216 字节，没有 Content-Encoding，缓存 max-age=0，一次无缓存下载 27.24 秒。院落请求由 3 MB 主程序初始化后触发，页面空壳和半成品场景先显示。

实施：不减少模型精度；构建阶段生成 Brotli/gzip 副本，静态服务器协商压缩，哈希脚本和带内容版本的模型长期缓存。HTML 自带轻量加载遮罩，提前预加载院落；轻量入口并行请求模型与主程序，实际字节驱动下载进度。解析模型、生成反射和光照后完成首帧才移除遮罩。失败保留遮罩并提供重试。游戏菜单在加载完成前 inert，不可误开局。

验证：压缩协商、缓存、HEAD/条件请求及原始文件回退测试；前缀构建；真实冷启动浏览器截图、进度、失败重试与资源性能；Docker 部署后冷缓存传输对比和公网双客户端联机回归。现有 Nginx 其他服务配置不改。


实施记录：加载界面/并行下载、预压缩与缓存均完成；67 项测试通过，慢网和失败浏览器验证通过。首轮公网 gzip 传输 5,031,240 字节、13.59 秒，对比原始 9,900,216 字节、27.24 秒；两个模型解压后 SHA-256 一致。服务端已额外验证常见浏览器同时声明 gzip/deflate/br 时优先选择 Brotli。

最终公网 Brotli 复测：4,355,090 字节、11.80 秒，响应 Content-Encoding: br；带正确模型内容版本时 Cache-Control: public, max-age=31536000, immutable。线上 Chrome 初次打开显示实际 20% 院落下载进度。
